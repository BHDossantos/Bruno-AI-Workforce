# Insurance day-10 booking check-in (draft; no live sender)
This stage is a deterministic proposal engine, not an enabled integration. It adds no scheduler, provider, database schema, endpoint, credential, or messaging change. It is distinct from the pre-sale lead cadence. Feature flag must default off in any later integration. No historical backfill.
## Customer experience
- Enroll only verified new bound personal-lines households in MA/NH on a new, named pilot cohort after approval. Coalesce policies bound in the same sales cycle into the same stable ID. Never enroll quote requests or stale leads.
- On day 10 local, or the next staffed Eastern window (default pilot proposal: 9–5 weekdays, configured closed dates), propose one booking invite via the customer's explicitly selected, currently permitted SMS **or** email. Do not default an unknown preference, fire both, or copy a booking URL from inbound data.
- Optional check-in, not a condition of coverage. Draft: “Hi [first name], this is [agency] checking in on your new policy. If you’d like to go over your coverage or ask a question, choose a time here: [approved booking link].” Use the approved channel's identification, contact permissions, and opt-out text. No savings claim; the producer can offer comparison if asked.
- 24 elapsed hours after successful provider acceptance, if still no booking/reply and calling is permitted, propose one callback task assigned to an identified licensed human in the next staffed window. Provider acceptance is not proof of delivery. Treat failed/bounced/uncertain delivery separately, not as an automatic resend or fallback. Before any human dials, re-check the latest consent, contact window, reply and booking. Never auto-dial.
## Integration requirements before live use
1. Map authoritative policy bind date/state, permission and opt-outs per channel, current active policy, producer assignment, and an approved booking URL. Build stable party/case mapping with minimal PII. Initial cases only from a controlled cohort; no retroactive scheduled sends.
2. Persist the stable case key and reserve each deterministic action key transactionally (unique constraints on case, invite and callback). Re-evaluate source flags under lock prior to enqueue/callback. A provider timeout without reliable outcome goes to manual review, never automatic resend. Use the existing outbound suppression guard, not a parallel sender. Record intent, provider receipt, message ID, channel, timestamp, policy version and audit outcome. Do not add a separate mass lead-cadence enrollment.
3. Reconcile actual provider replies, booking confirmations and opt-outs via trusted events; correlate by case/send IDs, validate and deduplicate event IDs, and close already queued callbacks on booking/reply. If an authenticated cancellation for the matching booking has no confirmed replacement, reopen the single assigned human callback with a “booking cancelled without replacement” reason during staffed hours; preserve the same task record. Use a unique action key per booking, reconcile any late rebooking before the worker or human acts, and respect reply/opt-out flags. Do not send another automated invite. Avoid storing message contents if event metadata suffices.
4. Map the existing human task queue to the assigned producer and status. Keep stale/cancelled tasks visible as closed and suppress on latest DNC or inactive policy. No automatic calls.
5. Test in nonproduction with synthetic contacts and fake adapters: two workers racing; provider fail/timeout/late bounce; duplicate and out-of-order webhook; booking/reply after reservation; opt-out between scheduling and dispatch; staffing holidays/DST; task once per cycle. Confirm selected live sender, callback authentication, intake, suppression and existing Thrust hold before asking to activate any live pilot. An open draft and green unit tests are not readiness.
## Tracking
Per cohort: new binds, eligible households, invite proposals, provider-accepted vs delivered, direct bookings, replies, suppressed/failed, callback tasks, human check-ins and optional second policies. Aggregate only in shared notes. Producer handles all advice and quoting.
